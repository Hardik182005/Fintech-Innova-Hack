# CredenceAI — End-to-End Verification Specification

> Supplied by the project owner as the **final acceptance gate**, to be executed
> *after* the GCP deployment is complete. This file is the authoritative
> checklist; `docs/TEST_LOGIC_REPORT.md`, `docs/TEST_COVERAGE_MATRIX.md` and
> `docs/KNOWN_LIMITATIONS.md` are its required outputs.
>
> Sandbox only. Test credits only. No real money, no real personal data, no
> production wallets, no real financial credentials.

## Mission

Verify the running application end to end through Google Chrome — not by code
review, not by unit tests alone. Start the full stack, drive every major
feature through the browser as a real user would, verify the backing APIs,
run the complete credit lifecycle from agent registration through repayment,
exercise adverse/security/privacy/failure/recovery paths, confirm every
dashboard and System Intelligence figure derives from real recorded events,
fix genuine defects, retest each affected flow, and report with evidence.

## Standing rules

- Chrome in headed mode; Chrome DevTools MCP preferred, else Playwright/Chromium headed.
- Drive the UI first. APIs are for verification, synthetic seeding, and response inspection — never to paper over a broken UI.
- Never substitute frontend mock data for broken functionality.
- Never hardcode a passing metric.
- Never hand-edit database rows to fake a successful scenario (documented test fixtures excepted).
- Never suppress browser, backend, policy, model, or database errors.
- Never weaken a security control to make a test pass.
- Never expose chain-of-thought, tokens, passwords, private keys, or credentials in screenshots or reports.
- Thread correlation IDs so browser action → API request → pipeline event → audit event can be traced as one story.
- **A controlled policy rejection is a successful safety outcome, not a pipeline failure.**
- An unexpected 4xx/5xx, JS exception, schema error, or inconsistent financial balance **is** a defect.
- Fail closed whenever identity, evidence, scoring, policy, or repayment integrity cannot be verified.

## Sections

1. **Testing principles** — as above.
2. **Environment discovery** — document repo layout, frontend routes, backend entry point, DB config, auth/session design, local model config, policy engine, deterministic credit engine, restricted vault logic, repayment logic, audit chain, synthetic scenario endpoints, GCP deploy config, existing test suites, env vars, available Chrome/Playwright tooling. Report configuration only as present / missing / malformed / unsafe / unavailable — **never print secret values**. Confirm the visible sandbox label: `Sandbox — Test Credits Only. No Real Money.`
3. **Start the full application** — real health checks (not "the process started") for frontend, FastAPI, PostgreSQL, pgvector/retrieval, policy engine, deterministic credit engine, primary local model, independent verifier, embedding model, reranker, PII redaction, worker/queue, vault service, repayment service, audit-chain service. Record name, port, health response, version, startup errors, startup duration.
4. **Controlled synthetic dataset** — idempotent fixture under `Synthetic Commerce Labs Pvt Ltd`. Roles: Org Admin, Risk Officer, Underwriter, Auditor, read-only Judge. Six agents:
   - **A** strong performer → expect low-risk approval
   - **B** new agent, thin history → expect human review or reduced limit
   - **C** poor repayment history → expect rejection or small limit
   - **D** suspicious spending (splits, unknown vendors, velocity anomalies) → expect restricted/frozen
   - **E** expired authorization → expect fail-closed rejection
   - **F** revoked passport → expect total denial of new credit and spending

   Seed synthetic task/repayment/spending history, applications, vendors, allowlists, blocked counterparties, risk events, human reviews, completed repayments, audit events. Re-runs must not duplicate orgs or agents.
5. **Chrome requirements** — 1440×900 first, then tablet and mobile. Capture screenshots, console logs, failed requests, request/response summaries, traces, and videos where supported into `artifacts/e2e/YYYY-MM-DD_HH-mm-ss/`. Redact auth headers, cookies, tokens, secrets, PII, private financial identifiers.
6. **Application shell** — sidebar (black), main (white), collapse, active route, mobile drawer, header, breadcrumbs, org selector, user menu, environment badge, language selector, notifications, logout, session expiry, unauthorized-route handling. Confirm no demo token or secret appears in page content, HTML, bundle, source maps, local/session storage, network payloads, console, or error messages. Walk every route: `/dashboard`, `/agents`, `/credit-applications`, `/underwriting`, `/vaults`, `/transactions`, `/repayments`, `/risk`, `/audit`, `/system-intelligence`, `/judge-demo`, `/settings`, `/developer/console` — recording status, load time, title, API calls, console errors, result.
7. **Dashboard** — Active Agents, Outstanding Credit, Active Vaults, Repayment Rate, Principal Recovered, Blocked Transactions, Prevented Exposure, Recent Applications, Live Risk Events, Repayment Health, Audit Integrity. Cross-check ≥5 values against DB/API aggregates, documenting displayed value, source endpoint, source record count, independently calculated expectation, pass/fail. Verify loading/empty/error states, refresh, time and INR formatting, responsive layout. **No metric may be hardcoded.**
8. **Agent registration & passport** — register via UI, link to org, set permitted categories, max borrowing authority, expiry; issue passport; verify details page. Confirm agent ID creation, verifiable owner link, passport status, stored limits, enforced expiry, audit events, and that no signing material is exposed. Negative: duplicate registration, malformed input, unauthorized owner, expired authorization, revoked passport, cross-org access.
9. **Happy-path pipeline (Agent A)** — e.g. ₹1,000 requested against ₹1,800 expected revenue, allow-listed synthetic vendors, 30-minute duration. Verify all stages: request received → schema validation → passport verification → evidence retrieval → task analysis → feature calculation → AI underwriting recommendation → deterministic credit calculation → independent risk verification → policy evaluation → human review (when required) → final decision → restricted vault creation → controlled vendor spending → task completion → revenue collection → repayment waterfall → audit finalization. Per stage record correlation ID, input/output summary, status, duration, audit event, applicable policy, browser-visible state. Confirm the AI recommendation is evidence-grounded, the deterministic maximum is independently calculated, the approved amount never exceeds policy limits, the vault is task-specific, only allow-listed vendors can be paid, the mandate exists, revenue lands in the controlled account, repayment executes automatically, surplus releases only after repayment, the ledger balances, and the audit chain verifies. Validate exactly, decimal-safe:

   ```
   Incoming Revenue = Principal Recovered + Credit Fee + Platform Fee + Owner Proceeds
   ```

   **A one-paise mismatch is a failure.**
10. **Reduced-limit decision (Agent B)** — request above the safe amount; display Requested / AI Recommended / Deterministic Maximum / Policy Maximum / Final Approved. Final must never exceed the lowest hard limit, and the UI must explain the reduction.
11. **Rejection (Agent C)** — weak repayment evidence, insufficient revenue. Confirm no vault, no funds released, policy reason shown, audit event written, dashboard updated, zero exposure created.
12. **Human review** — force a valid `HUMAN_REVIEW_REQUIRED`. Through the UI: open the queue, inspect evidence, approve within the deterministic limit, request more evidence, reject, verify role permissions. A reviewer must not be able to approve above the deterministic or policy maximum. Test unauthorized reviewer access.
13. **Restricted vault** — verify approved/utilized/remaining, task ID, owner, agent, allow-listed vendors, transaction/task/daily limits, expiry, status, mandate. The agent must not be able to withdraw unrestricted credits, change the repayment destination, add an unknown vendor, modify its own limit, extend its own expiry, or reactivate itself after revocation.
14. **Overspend** — ₹2,000 attempted against a ₹1,000 vault. Expect block, no ledger debit, risk event, correct prevented exposure, exact policy reason in the UI, audit event, balanced vault. **Enforced server-side** — repeat the attempt directly against the API and confirm it is still blocked.
15. **Unknown vendor** — personal wallet, unknown vendor, blocked vendor, malformed counterparty. Expect block, no movement, correct rule shown, risk event, audit event, accurate prevented amount. Test UI and direct API bypass.
16. **Split-payment attack** — 5 × ₹400 against a ₹1,000 task limit. Verify aggregation/velocity detection, blocking past the cumulative policy, freeze per configured policy, no extra credits leaving the vault, dashboard/risk updates, and one correlation or attack group linking all attempts. Test slower splits if a time-window rule exists.
17. **Kill switch** — begin a valid pending transaction, revoke/freeze as owner or Risk Officer, attempt execution. Expect cancellation or prevented settlement, denial of future requests, visible agent and vault state change, revocation in the audit chain, and no movement after the effective revocation. Report kill-switch request timestamp, effective revocation timestamp, blocked transaction timestamp, observed latency. **Do not describe a settled transaction as reversible.**
18. **Task failure** — fail a task after partial permitted spending. Verify configured recovery: freeze remaining, sweep unused, use reserve, calculate explicit lender loss, update trust/risk history, reduce future credit, write audit events. The system must not claim full repayment when funds are unavailable. Display original credit, spent, unused recovered, reserve used, lender loss, final ledger state.
19. **Repayment enforcement** — full repayment, partial revenue, revenue below principal, duplicate/replayed revenue event. Verify idempotency, principal cannot be recovered twice, duplicates do not duplicate repayment, fees calculated once, correct surplus, balanced ledger, fail-closed on a broken invariant. The agent must not be able to redirect incoming revenue.
20. **Identity & authorization attacks** — expired passport, revoked passport, foreign-org agent, altered agent ID, forged org ID, missing authorization, reused authorization, and task / vendor / amount changed after approval. Expect rejection, no fund-releasing decision, no vault created or changed, audit and security events, and no cross-tenant reachability.
21. **Multi-tenant isolation** — two synthetic orgs; A must not list B's agents, applications, vaults, transactions, repayments, risk events, audit records, or judge scenarios, nor infer B's totals from aggregates. Test UI navigation, direct API calls, altered URL IDs, query parameters, request bodies. **Any cross-tenant leak is critical.**
22. **AI quality & hallucination** — labelled synthetic dataset covering supported, contradictory, missing, irrelevant, and malicious evidence; injection in task descriptions and in retrieved records; malformed model output; unsupported financial claim; wrong repayment-history, task-success, and owner claims. Verify claims carry valid evidence IDs, unsupported claims are rejected, `INSUFFICIENT_EVIDENCE` is used where appropriate, the output schema is enforced, deterministic calculations are never delegated to the LLM, the verifier challenges unsupported recommendations, and the LLM can neither approve credit, call payment tools, nor modify policy. Chain-of-thought stays hidden. Compute from real results: Evidence Grounding Rate, Hallucination Containment Rate, Structured Output Validity, Verifier Disagreement Rate, Human Escalation Rate, Model Retry Rate — **always with sample size**.
23. **Fail-closed** — inject one at a time: primary model down, verifier down, malformed model JSON, evidence retrieval down, transient DB failure, policy engine down, PII redaction down, audit write failure, credit-risk model error, repayment imbalance, duplicate transaction, queue timeout, stale authorization, service restart mid-request. Acceptable outcomes: credit not approved, funds not released, transaction blocked, human review required, vault frozen, repayment held for reconciliation, safe retry, explicit degraded status. **No failure may silently allow money movement.** Restore each service afterwards.
24. **Audit chain** — every critical event produces an entry; correct sequence ordering; prev/current hash linkage; actor, object, timestamp, correlation ID present; verification passes. In a **disposable fixture only**, alter one record, confirm integrity fails, then restore. Never mutate shared audit data. Confirm the audit UI explains tamper detection clearly.
25. **System Intelligence page** — Assurance Score formula correct, only real evaluation data, visible sample count, missing components never silently zero, visible timestamp and dataset version. Cross-check live pipeline processed/allowed/blocked/controlled-rejection/error counts, p50, p95, queue depth. Open several request traces and match them to backend telemetry and audit events. Verify per-role metrics for Task Analyst, Underwriting Analyst, Independent Risk Critic, Audit & Explanation Agent. Verify local inference: real model names, serving status, request counts, latency, queue depth, structured-output validity, and external LLM call count — **`External LLM API Calls: 0` must be derived from configuration and telemetry, never hardcoded**. Cross-check AI quality metrics, deterministic engine counts, financial safety figures, and every completed waterfall equation. Verify real privacy status for PII redaction, injection defence, policy enforcement, tool-broker restrictions, sensitive-logging controls, audit integrity, external egress. For GCP efficiency, validate GPU utilization/memory, replicas, restarts, autoscaling, queue depth, runtime, estimated cost where connected — otherwise display `Billing data not connected` or `Metric unavailable`, never fabricated savings. Force one safe degraded state and confirm the page does not still show everything healthy.
26. **Translation** — English, Hindi, one more configured language. Verify navigation, page labels, explanations, statuses, tooltips, and number/currency formatting. Never translate IDs, hashes, model names, event codes, or API routes. Switching language must not alter any financial value or business logic.
27. **ElevenLabs voice** — only when configured, and only with redacted synthetic summaries. Verify narration can be requested; no PII, credentials, raw audit payloads, or raw financial records are sent; failure does not break the app; voice is optional and text remains available. Capture the redacted payload shape without exposing credentials. When unconfigured, verify graceful fallback.
28. **Frontend quality** — loading, empty, error, retry, stale-data indicators, confirmation dialogs, disabled states, success notifications, keyboard navigation, focus states, mobile responsiveness, table overflow, long identifiers, decimal and date formatting, accessibility labels. **Every visible dead button is a defect.**
29. **Network & browser health** — JS exceptions, React errors, hydration errors, failed requests, unexpected redirects, CORS failures, 401/403/404/409/422/500, slow requests, duplicate requests, exposed secrets, oversized payloads, aggressive polling, memory leaks across repeated navigation. Explain whether each non-2xx was expected or defective.
30. **API contract** — for every endpoint the browser calls: method, route, auth requirement, request/response schema, tenant enforcement, idempotency, expected status codes, malformed-input behaviour, unauthorized behaviour, not-found behaviour, concurrency behaviour. Validate against Pydantic/OpenAPI/Zod. No page may silently accept schema-invalid data.
31. **Concurrency & idempotency** — two applications for one task, two reviewer actions, two vendor-spend requests, duplicate revenue receipts, duplicate repayment triggers, simultaneous freeze and spend, simultaneous completion and revocation. Verify locking, idempotency keys, no double spend, no duplicate vault, no duplicate repayment, a deterministic terminal state, and an understandable conflict response.
32. **Performance** (modest, no DoS risk) — 25 sequential requests, 10 concurrent credit requests, 20 policy checks, 10 repayment events, 10 dashboard refreshes. Measure API p50/p95, model p50/p95, pipeline end-to-end p50/p95, policy latency, DB latency, page load, error rate, queue depth, resource utilization. **Label the test size and make no production-scale claims from it.**
33. **GCP deployment smoke test** — deployed URL, HTTPS, correct environment label, route loading, API connectivity, private model endpoint, DB connectivity, policy engine, background jobs, audit writes, logs/monitoring, no public model endpoint, no browser-visible secrets. Minimum flows: login, dashboard, agent view, credit application, overspend block, repayment, audit verification, System Intelligence. Do not deploy or modify production resources without existing authorization. Use configured credentials without printing them.
34. **Automated suites** — frontend lint, typecheck, unit, component; browser E2E; backend lint, typecheck, unit, integration; policy, credit-engine, repayment-invariant, audit-chain, security tests; production frontend build; backend startup; container build. Report exact command, passed/failed/skipped counts, duration, and important warnings — **never just "tests passed"**.
35. **Defect handling** — per defect: ID, severity, affected feature, reproduction, expected, actual, root cause, smallest safe fix, regression test, retest of the original and related scenarios. Severity: **Critical** (data leak, unauthorized money movement, cross-tenant exposure, secret exposure), **High** (broken core credit/vault/policy/repayment logic), **Medium** (important feature incorrect or unavailable), **Low** (visual/usability/non-blocking). **Do not hide unresolved defects.**
36. **Required reports** — `docs/TEST_LOGIC_REPORT.md` (executive summary; system under test incl. commit SHA and versions; architecture verified; feature-by-feature results; full pipeline results; financial logic verification with independently calculated figures; AI evaluation with dataset version and sample size and failed examples; security & privacy; browser & API health; performance with test size; GCP verification; defects fixed with before/after evidence; unresolved limitations, honestly; final readiness rated separately for Hackathon Demo / Core Logic / Security / Market), plus `docs/TEST_COVERAGE_MATRIX.md`, `docs/KNOWN_LIMITATIONS.md`, and `artifacts/e2e/<timestamp>/test-results.json`. **Do not call the project market-ready while material limitations remain.**
37. **Coverage matrix** — columns: Requirement | Feature | UI Test | API Test | Negative Test | Evidence | Result. Cover verified agent↔principal link, alternative underwriting, programmable issuance, programmable repayment, credit limits, real-time monitoring, instant revocation, trust design, repayment enforceability, risk containment, technical soundness, real-world plausibility — plus privacy, tenant isolation, hallucination containment, deterministic calculations, auditability, GCP deployment, local inference, multilingual support, optional voice.
38. **Acceptance criteria** — every primary page opens in Chrome; no critical browser error; no unexpected 500; no dead button; dashboard matches real aggregates; passport correctly links agent and owner; decisions use real evidence; the AI can neither approve nor release funds; the deterministic maximum is enforced; unknown vendors blocked; overspending blocked; split-payment bypass detected; revoked agents cannot spend; expired agents cannot request credit; the waterfall balances exactly; duplicate repayment prevented; task failure reports real loss; cross-tenant access blocked; audit tampering detectable; System Intelligence comes from real telemetry; missing telemetry shows as unavailable; external LLM usage accurately reported; no secret or PII exposed; local and deployed smoke tests pass; regression tests pass; production build succeeds; the report carries supporting evidence.
39. **Final response** — overall result (PASS / PASS WITH LIMITATIONS / FAIL), commit SHA, local URL, deployed URL, UI scenario count, API check count, tests passed/failed/skipped, critical & high defects found, defects fixed, remaining limitations, paths to the three reports plus screenshots/videos/traces/machine-readable results, exact commands used, and confirmation that no real money or real personal data was used.

> Do not claim everything works unless the Chrome evidence, API evidence,
> financial calculations, audit events, automated tests, and production build
> all support that conclusion.
